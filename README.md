# 💘 소개팅 매칭 엔진

**"왜 이 사람이 1위인지" 설명할 수 있는 소개팅 추천 + 매칭 채팅**

절대조건으로 거르고, 내가 정한 중요도로 점수를 매기고, 순위가 나온 이유를 항목별 숫자로 보여 줍니다.
마음에 드는 사람에게 좋아요를 보내고, 서로 좋아요를 누르면 채팅할 수 있습니다.

```
[전체 회원]
   │ ① 거르기      절대조건(흡연·음주·관심사·나이 …)에 걸리면 점수와 상관없이 탈락  ← 양방향 검사
   ▼
   │ ② 후보 추리기  인원이 많으면 임베딩(문장 → 좌표)으로 비슷한 사람 top-K만 남김
   ▼
   │ ③ 점수·순위    겹치는 항목마다 중요도(5·10·15·20점)만큼 더하기. 관심사는 겹친 개수 × 중요도
   ▼
   │ ④ 설명        1위가 2위보다 어떤 항목에서 몇 점 앞섰는지, 중요도 설정 때문에 순위가 바뀌었는지
   ▼
[추천] → ♥ 좋아요 → 서로 좋아요 = 매칭 → 💬 채팅
```

## 빠른 실행

Python 3.10 이상이 필요합니다.

```bash
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt      # Windows
.venv\Scripts\python -m uvicorn app.main:app --reload
```

macOS / Linux는 `.venv\Scripts\python` 대신 `.venv/bin/python`을 쓰면 됩니다.

- 웹 화면: http://127.0.0.1:8000
- API 문서(Swagger): http://127.0.0.1:8000/docs
- 터미널로 보기: `python scripts/demo.py 1` (1번 사용자 기준 추천)
- 테스트: `pytest`

오른쪽 위 **⏻ 종료** 버튼을 누르면 서버가 꺼집니다(서버를 실행한 컴퓨터에서 접속했을 때만 동작).

#### 휴대폰으로 접속하기

화면은 휴대폰 크기에 맞춰 바뀝니다. 휴대폰에서 열려면 PC와 **같은 와이파이**에 연결한 뒤:

```bash
.venv\Scripts\python -m uvicorn app.main:app --host 0.0.0.0 --port 8000
```

PC의 IP 주소(`ipconfig`의 IPv4 주소, 예: `192.168.0.10`)로 휴대폰 브라우저에서 `http://192.168.0.10:8000`에 접속합니다.
Windows 방화벽 허용 창이 뜨면 "개인 네트워크"만 허용하세요. 공용 와이파이에서는 쓰지 마세요(로그인이 없어 누구나 접속할 수 있습니다).

### 데이터는 계속 남습니다

처음 실행할 때만 가상 프로필 20명(`data/sample_*.json`)으로 시작하고, 그 뒤로는 **각자 컴퓨터의 `data/profiles.json`, `data/social.json`에 계속 저장**됩니다.
이 파일들은 `.gitignore`에 들어 있어서 깃허브에 올라가지 않고, `git pull`로 새 코드를 받아도 바뀌지 않습니다.

| 상황 | 어떻게 지키나요 |
|---|---|
| 서버를 껐다 켬 | 프로필·중요도·거르기 조건·좋아요·채팅이 모두 그대로 |
| 중요도·조건을 바꾸고 저장 버튼을 안 누름 | **자동 저장** (바꾸는 즉시) |
| 코드가 바뀌어 예전 데이터와 안 맞음 (예: 점수 항목 삭제, 선택지 변경) | 서버가 멈추지 않고 **맞지 않는 값만 정리**. 이름·나이·직업 같은 프로필의 큰 틀은 유지. 정리하기 전 원본을 `data/backups/`에 백업 |
| 필수 항목이 깨져 도저히 못 읽는 프로필 | 지우지 않고 `data/profiles_보류.json`으로 옮겨 둠 |
| 저장 도중 꺼짐 | 임시 파일에 먼저 쓰고 한 번에 교체해서 기존 파일이 깨지지 않음 |
| 실수로 "가상 데이터로 되돌리기"를 누름 | 지우기 전에 `data/backups/`에 자동 백업 |
| 서버를 켤 때마다 | `data/backups/`에 백업 (최근 30개 보관) |

새 버전을 **다른 폴더에 새로 받는 경우**에는 기존 `data/profiles.json`, `data/social.json`을 새 폴더의 `data/`로 복사하거나,
`.env`에 `MATCH_DATA_DIR=C:/Users/내이름/Documents/소개팅앱-데이터`처럼 프로젝트 밖의 폴더를 지정해 두면 어느 버전에서 실행해도 같은 데이터를 씁니다.

백업에서 되돌리려면 서버를 끄고 `data/backups/`의 파일을 `data/profiles.json`(또는 `social.json`)으로 복사한 뒤 다시 켜면 됩니다.

## 매칭 로직

### ① 거르기: 절대조건

절대조건에 하나라도 걸리면 **점수가 아무리 높아도 탈락**합니다.

| 조건 | 의미 | 예시 |
|---|---|---|
| `exclude` | 상대 값이 목록에 있으면 탈락 | 흡연: `흡연` 제외 / 음주: `자주` 제외 |
| `require` | 상대 값이 목록에 없으면 탈락 | 원하는 관계: `진지한 연애`, `결혼 전제`만 허용 |
| `min` / `max` | 범위를 벗어나면 탈락 | 나이 25 이상, 학력 대졸 이상 |
| 관심사 `exclude` | 이 관심사 중 하나라도 있으면 탈락 | 관심사에 `게임` 있으면 제외 |
| 관심사 `require` | 이 관심사 중 하나도 없으면 탈락 | 관심사에 `등산`, `캠핑` 중 하나 필수 |

조건을 걸 수 있는 항목은 흡연, 음주, 관심사, 나이, 키, 학력, 지역, 운동 빈도, 종교, 원하는 관계, 데이트 스타일, 연락 빈도, MBTI입니다.

- **양방향 검사**: 내 조건에 상대가 걸리는지, 상대 조건에 내가 걸리는지 둘 다 확인합니다. 상대가 거절할 사람을 추천해 봐야 의미가 없으니까요.
- **정보 미입력 = 탈락**: 절대조건 항목을 상대가 입력하지 않았다면 조건을 만족하는지 확인할 수 없으므로 탈락시킵니다. (관심사 제외 조건은 예외: 관심사가 비어 있으면 그 관심사도 없는 것으로 봅니다.)
- **흡연·음주는 점수에 넣지 않습니다.** 싫으면 아예 안 만나는 항목이라 거르기 조건으로만 씁니다.
- 탈락한 사람도 화면 하단에 **이유**와 *점수만 보면 몇 점이었는지*를 함께 보여 줍니다.

#### 문장으로 조건 만들기

"이런 사람은 걸러요"를 문장으로 적으면 조건 후보를 만들어 줍니다 ([textrules.py](matcher/textrules.py), 규칙 기반이라 설치 필요 없음).

```
"담배 피우는 사람은 싫어요. 술 자주 마시는 사람도 별로고, 게임 좋아하는 사람은 패스. 27살 이상이었으면 좋겠어요."
 → 흡연: 비흡연만 허용 / 음주: 자주 제외 / 관심사에 게임 있으면 제외 / 나이: 27 이상
```

- 자동으로 바로 적용하지 않고 **후보만 보여 준 뒤, 사용자가 확인하고 추가**합니다. 문장을 잘못 이해해서 사람이 몰래 걸러지는 일을 막기 위해서입니다.
- 이해하지 못한 문장(예: "성격 좋은 사람")은 따로 표시합니다.

### ② 후보 추리기: 임베딩

거르기를 통과한 사람이 `CANDIDATE_TOP_K`(기본 100명)보다 많을 때만 동작합니다.
프로필 글(자기소개, 질문 답변, 관심사)을 벡터로 바꾼 뒤 나와 코사인 유사도가 높은 top-K명만 ③단계로 넘깁니다.

- 기본값은 설치가 필요 없는 **글자 n-gram 해싱 임베딩**입니다. 같은 단어를 쓰는지를 봅니다.
- `pip install -r requirements-ai.txt` 후 `EMBEDDER=sbert`로 설정하면 **의미 기반 임베딩**(`multilingual-e5-small`)을 씁니다.
- 참고: 이건 RAG가 아니라 **벡터 유사도 검색**입니다.

### ③ 점수: 겹치면 중요도만큼

```
관심사    = 중요도 × 겹친 관심사 개수
나머지    = 같으면 중요도, 다르면 0
총점      = 전부 더한 값 (100점 만점으로 바꾸지 않음)
```

화면에서 항목마다 중요도를 고릅니다: **상관없음 0 · 낮음 5 · 보통 10(기본) · 중요 15 · 매우 중요 20점**

| 항목 | 점수를 받는 조건 | 예시 (중요도 10) |
|---|---|---|
| 관심사 | **겹칠 때마다** | 3개 겹침 → 30점 |
| 자기소개 | 문장 유사도가 40% 이상 | 56% → 10점 / 24% → 0점 |
| 원하는 관계·데이트 스타일·연락 빈도·운동 빈도·종교·MBTI | 같으면 | 둘 다 '진지한 연애' → 10점 |
| 지역 | 같은 시·도 | 둘 다 서울 → 10점 |
| 나이 차이 | 3살 이내 | 2살 차이 → 10점 |

- 관심사를 특히 중요하게 보도록 **관심사만 겹친 개수만큼** 점수를 줍니다. 중요도 20(매우 중요)으로 3개가 겹치면 60점입니다.
- 둘 중 한 명이라도 입력하지 않은 항목은 겹칠 수 없으니 0점이고, 화면에 "정보가 없어 계산에서 뺀 항목"으로 표시됩니다.
- 기준값(자기소개 40%, 나이 3살)은 [config.py](matcher/config.py)의 `BIO_MATCH_THRESHOLD`, `AGE_MATCH_YEARS`에서 바꿀 수 있습니다.
- **쌍방 모드**를 켜면 `(내 중요도로 계산한 점수 + 상대 중요도로 계산한 점수) ÷ 2`로 순위를 매깁니다.
- 동점이면 인증 회원 → 나이 차이가 적은 사람이 앞섭니다.

#### 추가 점수 규칙

거르기처럼 항목과 값을 골라서 **"여기에 해당하면 +5 · 10 · 15 · 20점"**을 줄 수 있습니다. 중요도 점수에 더해집니다.

| 예시 | 동작 |
|---|---|
| MBTI가 ENFP, INFP면 +15 | 상대 MBTI가 둘 중 하나면 +15 |
| 관심사에 등산, 캠핑이 있으면 +10 | 하나라도 있으면 +10 (규칙 하나당 한 번) |
| 키 175 이상이면 +5 / 나이 30 이하면 +5 | 숫자 항목은 이상·이하 |
| 학력 석사 이상이면 +10 | 학력은 해당·이상 |
| 지역이 서울이면 +5 | |

쓸 수 있는 항목: 흡연, 음주, 관심사, 나이, 키, 학력, 지역, 운동 빈도, 종교, 원하는 관계, 데이트 스타일, 연락 빈도, MBTI.
상대가 그 항목을 입력하지 않았으면 해당하지 않습니다. 쌍방 모드에서는 상대가 정한 추가 점수 규칙에 내가 해당하는지도 반영합니다.

#### 감점 규칙

추가 점수의 반대입니다. **"여기에 해당하면 −5 · 10 · 15 · 20점"**. 거르기처럼 아예 빼지는 않고 순위만 내립니다.

| 예시 | 동작 |
|---|---|
| 음주가 자주면 −10 | 술을 자주 마시면 10점 감점 |
| 관심사에 게임이 있으면 −5 | |
| 나이 35 이상이면 −15 | |

> **거르기 vs 감점**: 절대 안 되는 조건은 거르기, "되도록 피하고 싶은" 조건은 감점으로 쓰면 됩니다.

추천 카드에는 해당한 규칙이 ★(추가 점수) · ▼(감점)로 표시되고, 점수 배지에 `중요도 점수 + 추가 − 감점`이 나뉘어 보입니다.
규칙을 바꾸면 바로 다시 계산되고, 점수가 바뀐 사람은 ↑ / ↓ 변화량이 잠깐 표시됩니다.
**점수 계산 보기**에서는 [중요도 점수] · [추가 점수] · [감점] 구역으로 나눠 규칙마다 해당(✓)/미해당(✕)과 근거를 보여 주고, 마지막에 합계를 계산합니다.

#### 자기소개는 어떻게 점수가 되나요?

1. 자기소개 + 질문형 답변을 하나의 글로 합칩니다.
2. 두 사람의 글을 각각 벡터(좌표)로 바꿉니다(임베딩).
3. 두 벡터의 코사인 유사도(0~100%)가 40% 이상이면 "겹침"으로 보고 중요도만큼 점수를 줍니다.

기본 임베더는 **글자 조각(2~3글자)이 얼마나 겹치는지**를 봅니다. "등산하고 카페 가요"와 "산에 오르고 커피 마셔요"는 의미가 같아도 겹치는 글자가 적어 낮게 나옵니다.
`requirements-ai.txt` 설치 후 `EMBEDDER=sbert`로 바꾸면 **의미**로 비교하는 모델을 씁니다.

### ④ 설명: 왜 1위인가

LLM 없이도 항상 나오는 **규칙 기반 설명**입니다.

- 로직 흐름: 전체 N명 → 거르기 통과 → 후보 → 추천
- 1위와 2위의 **항목별 점수 차이**: 어떤 항목에서 몇 점 앞섰고 어떤 항목에서 뒤졌는지
- 중요도의 영향: *"중요도를 모두 보통으로 뒀다면 1위는 ○○님이었어요"*
- 사람마다 점수 계산식과 항목별 근거

`.env`에 `ANTHROPIC_API_KEY`를 넣고 화면에서 **AI 설명**을 켜면 상위 3명의 매칭 이유를 자연스러운 문장으로 다듬어 줍니다(선택 기능).
LLM에는 이름이나 회사 같은 개인정보를 보내지 않고 **공통점과 아쉬운 점만** 보냅니다.

## 좋아요 · 매칭 · 채팅

| 단계 | 설명 |
|---|---|
| ♥ 좋아요 | 추천 카드에서 보냅니다. 한마디 메시지를 함께 보낼 수 있습니다. |
| 받은 좋아요 | 채팅 탭에서 누가 나를 좋아하는지, 함께 보낸 한마디를 봅니다. |
| 매칭 | **서로 좋아요**를 누르면 매칭되고 채팅방이 열립니다. 주고받은 한마디가 첫 메시지가 됩니다. |
| 채팅 | 매칭된 사람과만 대화할 수 있습니다. 3초마다 새 메시지를 확인하고, 안 읽은 메시지 수를 표시합니다. |
| 차단 | 대화와 좋아요가 지워지고 서로 추천에서도 빠집니다. |

- 모르는 사람이 일방적으로 메시지를 보낼 수 없도록 **매칭 전에는 메시지를 막았습니다.**
- 지금은 로그인 대신 화면에서 "누구로 접속할지"를 고릅니다. 1번 김민준으로 받은 좋아요에 답해 보거나, 3번 박서준으로 접속해 샘플 대화를 볼 수 있습니다.

## 실행 예시 (1번 김민준 기준)

김민준의 설정: 흡연자 제외, 나이 25~33세, 관심사 **매우 중요(20)**, 원하는 관계 **중요(15)**, MBTI **상관없음(0)**

```
① 거르기: 전체 19명 중 대상 아님(성별·차단) 9명, 절대조건 탈락 4명 → 6명 통과

1위 이서연 145점  (중요도가 모두 보통이었다면 2위)
2위 박지우 135점  (중요도가 모두 보통이었다면 1위)
3위 윤채원 105점

[왜 1위인가]
이서연님 145점 vs 2위 박지우님 135점 → 10점 차이로 1위예요.
 · 자기소개 +10점 — 1위 [유사도 56% (기준 40% 이상)] / 2위 [유사도 24% (기준 40% 미만)]
중요도를 모두 보통으로 뒀다면 1위는 박지우님이었어요.

[1위 점수 계산식]
관심사 20×3 + 자기소개 10×1 + 원하는 관계 15×1 + 지역 10×1 + 나이 차이 10×1
+ 데이트 스타일 10×1 + 연락 빈도 10×1 + 운동 빈도 10×1 + 종교 10×1 = 145점

[거르기로 탈락 — 점수와 무관]
 최하은 (점수였다면 145점)  ✕ 흡연 '흡연'
 강예린 (점수였다면 85점)   ✕ 나이 '24'
 서유나 (점수였다면 60점)   ✕ 흡연 정보 미입력
 정수아 (점수였다면 20점)   ✕ [상대 조건] 종교 '무교' (기독교만 허용)
```

## 가상 프로필 60명

- **1~20번**: 로직을 확인하려고 손으로 만든 20명 (남자 1~10번, 여자 11~20번). 아래 사례가 들어 있습니다.
- **21~60번**: [scripts/generate_profiles.py](scripts/generate_profiles.py)로 랜덤 생성한 남녀 각 20명. 나이·지역·학력·직업·라이프스타일·관심사·자기소개·거르기 조건·중요도·추가 점수/감점이 다양하고, 일부 항목은 일부러 비워 두었습니다(정보 미입력 상황).

더 만들고 싶으면:

```bash
.venv\Scripts\python scripts/generate_profiles.py --male 20 --female 20 --seed 7
```

기존 데이터는 지우지 않고 뒤에 추가합니다. 서버가 켜져 있으면 API로 추가하고, 꺼져 있으면 백업을 남긴 뒤 파일에 추가합니다. `--seed`를 바꾸면 다른 사람들이 만들어집니다.

손으로 만든 20명의 확인용 사례:

| 확인할 것 | 사례 |
|---|---|
| 점수가 높아도 절대조건이면 탈락 | 13 최하은: 1번과 거의 모든 게 같지만 흡연자 |
| 상대 조건에 내가 걸림(양방향) | 14 정수아: 기독교만 허용 → 무교인 1번 탈락 |
| 정보 미입력은 절대조건 탈락 | 20 서유나: 흡연 정보 없음 |
| 관심사 겹친 개수 | 11 이서연, 12 박지우, 16 윤채원 모두 1번과 3개 겹침 |
| 중요도가 바꾸는 순위 | 1번 기준 이서연 ↔ 박지우 |
| 동성 매칭 | 9 장건우, 10 임태윤 (서로 남성 희망) |
| 학력 조건 | 17 임나연: 대졸 이상 |
| 관심사로 거르기 | 11 이서연: 관심사에 게임 있으면 제외 |
| 받은 좋아요 | 1 김민준: 이서연(한마디 포함)·박지우에게 좋아요 받음 |
| 진행 중인 대화 | 3 박서준 ↔ 16 윤채원 |

## 프로필 사진

- 모든 프로필에 **애니메이션 캐릭터가 자동으로** 들어갑니다. 코드가 직접 그리는 그림이라 설치나 인터넷, 비용이 필요 없습니다. 머리 모양·머리색·피부·눈·표정·안경·볼터치·옷 색이 사람마다 랜덤으로 조합됩니다.
- **🎲 캐릭터 바꾸기**: 다른 캐릭터로 바꿉니다.
- **📷 사진 올리기**: 실제 사진을 올릴 수 있습니다. 브라우저에서 가운데를 정사각형으로 잘라 400px로 줄인 뒤 `data/photos/`에 저장합니다(JPG·PNG·WEBP, 최대 3MB). 이 폴더는 깃허브에 올라가지 않습니다.
- 회원가입할 때도 사진을 고를 수 있고, 안 고르면 캐릭터가 들어갑니다.

## 프로필 항목

| 구분 | 항목 |
|---|---|
| **필수** | 이름, 성별, 최종학력, 직업, 나이(만 19세 이상), 시·도 |
| 기본 | 닉네임, 구/시, 키, 회사, 인증 여부 |
| 라이프스타일 | 흡연, 음주, 종교, 운동 빈도, MBTI |
| 관심사 | 30개 태그 중 최대 10개 |
| 연애 성향 | 연락 빈도, 데이트 스타일, 원하는 관계 |
| 자기소개 | 자유글 + 질문형 답변 |

## API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/api/options` | 선택지 목록 |
| GET | `/api/profiles` | 전체 프로필 |
| POST | `/api/profiles` | 프로필 등록 (필수 항목이 없으면 422) |
| PUT | `/api/profiles/{id}/preferences` | 중요도·절대조건 저장 (화면에서는 자동 저장) |
| GET | `/api/data-status` | 데이터 저장 위치 · 백업 개수 · 정리 기록 |
| GET | `/api/profiles/{id}/photo` | 프로필 사진 (올린 사진 또는 캐릭터 SVG) |
| PUT | `/api/profiles/{id}/photo` | 사진 올리기 (`data_url`) |
| POST | `/api/profiles/{id}/avatar` | 다른 캐릭터로 바꾸기 |
| POST | `/api/dealbreakers/parse` | 문장 → 절대조건 후보 |
| POST | `/api/recommend` | 추천 실행 |
| POST | `/api/likes` | 좋아요 보내기 (`message`로 한마디) → `{matched}` |
| GET | `/api/users/{id}/inbox` | 받은 좋아요 · 매칭 목록 · 안 읽은 메시지 수 |
| GET | `/api/chats/{id}/{other_id}` | 대화 보기 (매칭된 경우만) |
| POST | `/api/chats/{other_id}` | 메시지 보내기 (매칭된 경우만) |
| POST | `/api/block` | 차단 |
| POST | `/api/reset` | 가상 데이터로 초기화 |
